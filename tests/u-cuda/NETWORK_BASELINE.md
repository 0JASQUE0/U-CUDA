# Network: baseline и benchmark (этап 1.1)

Первый проверенный запуск: [результаты 31 октября 2026](NETWORK_RESULTS_2026-10-31.md).

Инструмент `network_test.cpp` собирается существующим MSBuild-тестовым скриптом,
без изменения `.vcxproj` и CMake. Требуется Release-сборка приложения и настоящий
CUDA GPU. Код 77 означает пропуск, а не успешную GPU-проверку.

```powershell
& 'C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe' U-CUDA.sln /p:Configuration=Release /p:Platform=x64 /m
tests\u-cuda\run_tests.bat network
```

Скрипт ищет Visual Studio через `vswhere` и обновляет runtime kernels из
`x64/Release/kernels`. Папка `tests/u-cuda/build` игнорируется Git.

## Модели и охват

`network_fixtures.h` содержит минимальные FHN и Hindmarsh–Rose: явные уравнения,
порядок параметров, значения и начальные условия. Время, состояния и коэффициенты
безразмерные; физическая калибровка здесь не подразумевается.

- FHN: `v'=v-v^3/3-w+I`, `w'=(v+a-b*w)/tau`;
  `I=0.5, a=0.7, b=0.8, tau=12.5`, начальные `(-1,1)`.
- HR: `x'=y-a*x^3+b*x^2-z+I`, `y'=c-d*x^2-y`,
  `z'=r*(s*(x-xr)-z)`; `a=1, b=3, c=1, d=5, r=0.006, s=4,
  xr=-1.6, I=3.25`, начальные `(-1.3,-7,3)`.

24 случая: две модели × Euler/RK4/CD × кольцо/звезда/направленная цепь/
направленный SmallWorld. По 16 узлов; `h=0.01`, 257 рабочих шагов, обычно
13 переходных, запись каждого третьего. Звезда проверяет нулевой переходный
процесс и автоматическое прореживание до лимита 37 точек.

Кольцо и звезда используют диффузионную связь первой переменной с нормировкой
по входящей степени. Цепь и SmallWorld — без нормировки, с чередованием
диффузионного и нелинейного закона `K*(x_j-x_i)/(1+x_j*x_j)` и весами
0.5/1.25. Общая сила связи 0.2. Последний параметр модели меняется по узлам
на `0.002*(i%5)` (tau для FHN, I для HR). НУ получают точные двоичные
смещения, seed топологии — 271828. Это фикстуры регрессии, а не протокол
оценки порога синхронизации.

Каждый случай проверяет повторный запуск, чанки 1/7/13/64/1000000 и включение
таймера. Сравниваются побитово вся траектория, статусы, диапазоны и временная
сетка. Проверяются конечность значений, отсутствие разлёта и отказ отрицательному
чанку. Границы чанков пересекают переходный процесс и моменты записи.
Дополнительно одиночный HR проверяется при `T=10.24` против независимо
рассчитанного CPU RK4 с тем же шагом: это проверка определения модели,
а не оценка погрешности интегрирования относительно точного решения.
`steps_per_launch=0` сохраняет прежний выбор; положительное значение задаёт
верхнюю границу, ограниченную также прежним автоматическим бюджетом TDR.

## Снятие и сравнение

```powershell
tests\u-cuda\build\network.exe --record tests\u-cuda\build\baseline-new
tests\u-cuda\build\network.exe --compare tests\u-cuda\build\baseline-new
```

Запись отказывает, если каталог уже существует. Сравнение не перезаписывает
эталон. По каждому случаю сохраняются полные входы (включая сгенерированные тела
КРС и связи, параметры, НУ и CSR) и двоичные результаты. Формат V1 — little-endian
Windows x64, с явными размерами векторов, без дампа padding структур.

Условия побитового равенства: тот же GPU (UUID), версия драйверного CUDA API,
NVRTC, MSVC, тип `numb`, настройки FMA/RDC, входы и runtime-исходники. Метаданные
`environment.txt` включают идентификацию GPU и точные тексты пяти загружаемых
файлов ядра. Несовпадение окружения или входов завершает проверку ошибкой.
Дата сборки инструмента записывается отдельно в `build.txt` и не участвует
в равенстве: инструмент можно пересобрать для проверки совместимой правки хоста.
Для сравнения другой GPU/драйвер требуется собственный baseline; пересоздание
эталона после правки не доказывает отсутствие регрессии.

В репозитории сохранён архив исходного baseline:
`fixtures/network-baseline-19b2087-rtx2060s.zip`. Он снят инструментом, связанным
с объектниками исходного движка `19b2087`, до изменения API чанков/таймера.
На подходящем окружении его можно проверить так (из корня репозитория):

```powershell
Expand-Archive tests\u-cuda\fixtures\network-baseline-19b2087-rtx2060s.zip tests\u-cuda\build\reference-19b2087
tests\u-cuda\build\network.exe --compare tests\u-cuda\build\reference-19b2087
```

Для исходной версии API предусмотрена сборка того же инструмента без новых
полей запроса и результата:

```powershell
$env:UCUDA_NETWORK_BASELINE='1'
tests\u-cuda\run_tests.bat network
# Затем --record; для новой версии убрать переменную и пересобрать тест.
Remove-Item Env:UCUDA_NETWORK_BASELINE
```

`UCUDA_TEST_BUILD_ONLY=1` позволяет только собрать тестовый executable, чтобы
затем запустить нужный режим вручную. В этом случае скрипт пишет `ALL BUILT`;
это не означает прохождения проверок.

## Benchmark

```powershell
tests\u-cuda\build\network.exe --benchmark tests\u-cuda\build\network-benchmark.csv
```

Для FHN и HR: RK4, кольцо степени 4, 16/64/256 узлов, 1024 шага,
`h=0.01`, без переходного процесса, запись каждого четвёртого шага (257 точек).
Три серии, перед каждой не менее 300 мс прогрева полными запусками;
по девять измерений в серии. CSV содержит все 27 измерений для каждого размера,
число дуг, точек и запусков. Консоль выводит минимум/медиану/максимум.

`gpu_ms` — сумма интервалов CUDA events вокруг каждого запуска ядра. Исключены
выделение памяти, H2D, ожидание на CPU, выгрузка и обработка диапазонов; интервал
может включать расходы планирования GPU между событиями. `full_ms` — синхронный
вызов `run_network` целиком, включая эти операции и выгрузку. Проверка тестом
конечности результатов выполняется после остановки таймера. NVRTC-модуль уже
скомпилирован при прогреве; холодная компиляция не измеряется. Events включены
только в benchmark/специальной проверке; обычный расчёт их не создаёт.

Частоты GPU не фиксируются. Сравнивать нужно одинаковые нагрузки и окружение,
учитывая разброс; эти замеры не являются пределом производительности GPU.
