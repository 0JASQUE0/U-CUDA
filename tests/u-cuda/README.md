# Тесты U-CUDA (MSBuild)

Файлы уровнем выше (`tests/*.cpp`, `CMakeLists.txt`) написаны для CMake-форка
(`CUDA-optimization`): там другие пути заголовков (`ucuda/...`), цели `ucuda::*` и
адаптивный решатель `adaptive::Solver`. В этом репозитории они не собираются и оставлены как
есть. Здесь — те же проверки, перенесённые на API U-CUDA, плюс тесты ДАУ.

| Тест | Что проверяет | Нужно |
|---|---|---|
| `gpu_smoke` | NVRTC компилирует тело шага, модуль грузится, траектория верна; комплексный путь находит `configCUDA.h`; свип БД считается | GPU |
| `krs_cpu` | cl.exe-шаг: сборка, счёт, кэш, отказ `X[i]` вне размерности, диагностика с номером строки | CPU |
| `adaptive` | CPU-драйвер адаптивного шага (плотный выход, осциллятор, допуск, неверные настройки); GPU = CPU; Лоренц против мелкого RK4; адаптивные LLE/LS (классика, продолжение, CPU = GPU); постоянный шаг: БД 2D, LLE/LS 2D, DFT, бассейны, FastSync; комплексные и неявные схемы | CPU, GPU |
| `architecture` | старый JSON сессии, круг JSON для стилей проекций и адаптивных настроек, очередь Parametric при удалении диаграммы, очередь DFT, отмена; записи систем ОДУ/ДАУ (старый формат, поля ДАУ) | CPU |
| `kicad` | KiCad (пропуск без него): все демо `demos\simulation` через kicad-cli в импорт (что прошло, что отвергнуто и почему); сверка переходного процесса с ngspice из `ngspice.dll` KiCad: выпрямитель и generic_opamp_bip из демо, BJT с C(v), MOSFET, JFET, K, B ?:, SFFM | CPU |
| `spice` | импорт SPICE-netlist'а в ДАУ: RC с SIN / PULSE / PWL против эталонной ОДУ, интегратор на TL072 в `.subckt` с параметрами, F/H, отказы; круговой тест Лоренц → синтез → netlist (B и POLY) → граф (та же топология) → ДАУ = `circuit_simulate`; импорт `tests/fixtures/lorenz_reference.cir` | CPU |
| `dae` | индексы, порядки (Radau IIA, Radau + GGL, SDIRK2, ROS3P, Rodas4), связь индекса 3, НУ со скрытыми связями, уровни A и C, отказы методов, разреженная LU; GPU: z0 в каждой точке свипа, LLE/LS на ДАУ, Radau + GGL GPU = CPU, отказ оси по z | CPU, GPU |

## Запуск

Сначала собрать `U-CUDA.sln` Release|x64. Затем:

```
tests\u-cuda\run_tests.bat            rem все
tests\u-cuda\run_tests.bat dae        rem один или несколько
```

Каждый тест собирается cl.exe против объектников `U-CUDA\x64\Release` (без `.vcxproj` и CMake),
запускается из `tests\u-cuda\build` со свежей копией `x64\Release\kernels`. Код выхода: 0 — прошёл,
77 — нет CUDA (GPU-часть пропущена), иначе — упал; итог — `ALL PASSED` / `SOME TESTS FAILED`.
`architecture` линкуется со всем приложением (сессии тянут типы окон графиков), остальные — только
с вычислительными объектниками.
