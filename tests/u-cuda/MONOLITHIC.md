# Монолитный эталон Network — пункт 1.2

[Результаты первого запуска и пробные карты](MONOLITHIC_RESULTS_2026-10-31.md).

Во вкладке Network кнопка **Save monolithic ODE to Library** сохраняет текущую
сеть отдельной обычной системой ОДУ. Существующий расчёт Network продолжает
использовать расщепление; экспортированная система включает связь в правую часть
и учитывает её на каждой стадии выбранной схемы.

Сохранённая запись независима от исходной системы и конфигурации сети. Общие
параметры сохраняются общими, непустое переопределение узла получает отдельное
имя (`I1`, `I2`). Переменные нумеруются с единицы (`x1`, `y1`, …). При конфликте
имён добавляется суффикс; исходный параметр `K` получает имя `K_model` или его
свободный вариант. Веса и деление на входящую степень явно записаны в уравнениях.
Общий множитель весов экспортируется как параметр `K`.

Смысл имён в законах связи сохраняется как в Network: переменные и параметры
модели перекрывают псевдонимы веса `K`/`w`. Если в исходной модели есть параметр
`K`, для веса в законе связи можно использовать `w`, пока это имя тоже свободно.
Генератор не меняет такой закон на другой молча.

Разброс начальных условий реализуется с теми же seed и алгоритмом, что в Network,
и сохраняется числами. Собственные НУ узла не получают дополнительного шума.
Кнопка выбирает свободное имя и сохраняет новую запись; существующие записи
не перезаписываются. Настройки исходной вкладки и её результаты не меняются.

Лимиты: 32 переменные состояния, 59 параметров модели (остальные пять слотов
массива `a[64]` заняты коэффициентом симметрии и настройками схем). Поддерживаются
обычные ОДУ, включая системы после развёртки вспомогательных функций; отображения
и системы ДАУ/алгебраические выходы отвергаются. Неверные индексы рёбер/законов
и некорректные значения параметров, НУ, разброса или весов вызывают ошибку до записи в Library.

Все встроенные схемы доступны в записи. Сырые пользовательские КРС исходного
нейрона не копируются: их индексы состояния и параметров относятся к одному узлу.
Нужную пользовательскую схему для всей системы можно добавить в редакторе Library.
Разные коэффициенты симметрии узлов не являются частью ОДУ: для монолитного шага
используется общий коэффициент из настроек конфигурации.

## Проверки и воспроизведение

После Release-сборки решения:

```powershell
tests\u-cuda\run_tests.bat monolithic
tests\u-cuda\build\monolithic.exe --export tests\u-cuda\build\pair-records
```

Тесты не используют локальную `library/`. Проверяются:

- направленная неоднородная сеть FHN из трёх узлов: положительные/отрицательные
  веса, разные законы, параметры источника/приёмника, обе настройки нормировки —
  против независимо выписанных правых частей;
- разбор LaTeX и замена целых символов через AST, включая сходные имена;
- конфликты имён, границы 32/59, ошибки графа и неподдерживаемые системы;
- JSON, восстановление порядка символов, сохранение и независимость записи;
- совпадение реализованного разброса НУ с настоящим запуском NetworkSession;
- пары FHN и HR: GPU RK4 против записанных вручную систем на коротком горизонте;
- сходимость Network к монолитному RK4 при `h=0.04, 0.02, 0.01`, `T=1`;
- запуск BD, LLE, LS и бассейнов для полученной обычной системы.

Проверка сходимости не оценивает порог синхронизации и не выбирает способ связи
для большого движка. Это отдельный протокол пункта 1.3.

## Первые карты: заранее заданный пробный протокол

```powershell
tests\u-cuda\build\monolithic.exe --maps tests\u-cuda\build\monolithic-maps
```

Режим сохраняет две записи систем и карты по `K` и общему току `I`. Это пробные
карты кластеров амплитуд пиков, а не доказанные периоды и не карты синхронизации.
Протокол фиксируется до расчёта:

| Параметр | FHN | HR |
|---|---|---|
| Модель/НУ | `network_fixtures.h`; у второго нейрона первая переменная +0.2 | то же |
| Граф | пара, одно двунаправленное ребро веса 1, связь первой переменной | то же |
| Нормировка | по входящей степени (для пары степень равна 1) | то же |
| Оси | `K∈[0,1]`, `I∈[0.2,1]` | `K∈[0,1]`, `I∈[2,4]` |
| Сетка | 16×16, линейная, включая концы | то же |
| Метод | монолитный RK4, `h=0.01` и `h=0.005` | то же |
| Переходный процесс | 200 | 1000 |
| Интервал наблюдения после него | 400 | 1000 |
| Наблюдаемая переменная | `v1` | `x1` |
| Кластеризация | `eps=0.02`, `mult_peak=1`, `mult_interval=0`; поиск пиков на каждом шаге | то же |

Каждая ячейка стартует с одних и тех же сохранённых НУ, без продолжения по сетке.
В CSV записываются обе классификации, чтобы расхождения при уменьшении шага
оставались видны. Коды движка: `-1` — неподвижная точка, `0` — разлёт/нет пригодного
результата, положительное число — число кластеров амплитуд пиков. Для научного
вывода ещё нужны проверка длительности наблюдения, нескольких НУ, метрики
синхронизации и оценка неопределённости по пункту 1.3.
