# Установка U-CUDA и настройка разработки

Единая инструкция по сборке проекта, правилам написания кода, MCP и скиллам Codex. Команды выполняются из корня репозитория — папки с `CMakeLists.txt`, а не из `.git`.

Исходные правила: [AGENTS.md](AGENTS.md), [архитектура](ARCHITECTURE.md), [навигация](README.md). Вложенные `AGENTS.md` дополняют общие требования. При изменении проекта обновляйте эту инструкцию вместе с соответствующими настройками.

## 1. Подготовка Windows

Установите:

- Git.
- Visual Studio 2022 или Build Tools 2022: инструменты C++ для рабочего стола, MSVC x64 и Windows SDK.
- CMake с поддержкой presets schema 6: **3.25 или новее**.
- NVIDIA CUDA Toolkit с поддержкой выбранной версии MSVC; для запуска GPU-вычислений также нужен совместимый драйвер NVIDIA и GPU.
- Python 3.10+ только при использовании OCR.

Версия CUDA Toolkit в репозитории не зафиксирована. Проверяйте совместимость Toolkit, host-компилятора и GPU перед установкой. Даже сборка без GUI требует CUDA Toolkit.

Откройте Developer PowerShell for VS 2022. Клонируйте репозиторий по своему URL либо перейдите в существующую копию:

```powershell
Set-Location 'E:\progs\CUDA\CUDA-optimization'
git status --short
cmake --version
nvcc --version
nvidia-smi
```

Путь выше — пример; на другом компьютере замените его. В Codex и IDE открывайте эту же папку.

## 2. Сборка и запуск

```powershell
cmake --preset windows
cmake --build --preset windows-debug
ctest --preset windows-debug
& .\build\windows\bin\Debug\U-CUDA.exe
```

После ошибки команды сначала устраните причину, затем продолжайте. Первая GUI-конфигурация требует сети: CMake получает закреплённые ревизии ImGui, ImPlot, ImPlot3D и при необходимости GLFW. Список зависимостей находится в [third_party/CMakeLists.txt](third_party/CMakeLists.txt).

Release:

```powershell
cmake --build --preset windows-release
ctest --preset windows-release
& .\build\windows\bin\Release\U-CUDA.exe
```

Presets задают `CMAKE_CUDA_ARCHITECTURES=75`. Если нужна другая архитектура, укажите значение для своей GPU при конфигурации или создайте локальный `CMakeUserPresets.json`; не меняйте общий preset ради одной машины.

Для старого пакетного приложения:

```powershell
cmake --preset windows -DU_CUDA_BUILD_LEGACY=ON
cmake --build --preset windows-debug --target U-CUDA-legacy
```

Отдельная сборка без GUI:

```powershell
cmake -S . -B build/headless -G 'Visual Studio 17 2022' -A x64 -DU_CUDA_BUILD_GUI=OFF -DU_CUDA_BUILD_LEGACY=ON
cmake --build build/headless --config Debug
ctest --test-dir build/headless -C Debug --output-on-failure
```

CMake — единственное определение сборки. Visual Studio может открыть корень как CMake-проект или сгенерированный `build/windows/U_CUDA.sln`. Рукописные `.vcxproj` и `.sln` не добавляются.

### Linux

Текущие presets ожидают Ninja, `/usr/bin/gcc-15`, `/usr/bin/g++-15` и CUDA в `/opt/cuda`. Для GUI нужны системные библиотеки разработки OpenGL и выбранного оконного backend GLFW. Сверяйте поддержку GCC с установленным CUDA Toolkit; пути другой установки задавайте локально.

```bash
cmake --preset linux-debug
cmake --build --preset linux-debug
ctest --preset linux-debug
./build/linux-debug/bin/U-CUDA
```

Для Release замените `linux-debug` на `linux-release`. Windows presets используют MSVC, не MinGW.

## 3. OCR и данные пользователя

В Windows необязательное OCR-окружение устанавливается отдельно:

```powershell
.\setup.ps1
```

Скрипт создаёт `.venv`, устанавливает [Python-зависимости](tools/ocr/requirements.txt) и записывает пользовательскую переменную `U_CUDA_PYTHON`. Установка тяжёлая; после неё перезапустите IDE, чтобы она получила переменную. Скрипт не устанавливает C++, CUDA, MCP или скиллы.

В Linux эквивалентное окружение можно подготовить так:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r tools/ocr/requirements.txt
export U_CUDA_PYTHON="$PWD/.venv/bin/python"
```

После сборки рядом с исполняемым файлом должны находиться `kernels/`, `library_template/`, `ocr_server.py` и необходимые Windows DLL. Переносите весь runtime-каталог, а не только `.exe`.

`U-CUDA/library/` содержит пользовательские данные: не удаляйте, не перезаписывайте и не заполняйте эту папку шаблонами вручную. Для другого расположения используйте `U_CUDA_LIBRARY`.

## 4. Правила написания кода

Перед правкой прочитайте README и AGENTS ближайшего модуля. Перед переносом кода между модулями прочитайте [ARCHITECTURE.md](ARCHITECTURE.md).

### Стиль и размещение

- Стандарты проекта — C++17 и CUDA C++17. Следуйте стилю окружающего кода; не смешивайте функциональную правку с массовым форматированием.
- Публичные заголовки размещайте в `libs/<module>/include/ucuda/<module>/`, внутренние — в `libs/<module>/src/`.
- Следуйте [.editorconfig](.editorconfig): по умолчанию UTF-8 с BOM, для Markdown/JSON/YAML/Python/TXT — UTF-8 без BOM. Сохраняйте MSVC `/utf-8`.
- `setup.ps1` сохраняйте ASCII-only согласно его собственному комментарию для совместимости с Windows PowerShell 5.1.
- Комментарии должны объяснять причины, ограничения и численные особенности. Не меняйте публичные контракты без проверки вызывающего кода.

### Архитектура и владение

- Зависимости направлены в одну сторону. Domain независим от CUDA, storage, application, plotting и UI; вычисления и storage собираются без GUI.
- CMake-зависимость объявляется `PUBLIC`, только если она нужна публичному заголовку; иначе используйте `PRIVATE`.
- Сессии содержат сериализуемые данные и вычислительное состояние. ImGui/OpenGL-ресурсы в них не помещаются.
- UI владеет представлениями, plotting — GL-ресурсами. Освобождайте их до уничтожения GL-контекста.
- Опрос фоновых задач, очередь, сохранение и отмена проходят через `AppModel::tick`, независимо от видимости окон.

### Численная и файловая совместимость

- Без явно запрошенного изменения поведения сохраняйте порядок операций, точность, FMA, аргументы ядер и значения по умолчанию.
- NVCC и NVRTC должны использовать одни источники device-алгоритмов. При изменении нужных заголовков и исходников проверяйте [упаковку runtime](cmake/PackRuntime.cmake).
- Сохраняйте загрузку старых JSON-сессий, записей систем, настроек и CSV-форматов. Для изменений сериализации добавляйте проверки старого формата и round trip.
- Не добавляйте в Git сборки, локальные presets, кеши, Python-окружение, пользовательские данные и секреты.

## 5. Настройка MCP в Codex

MCP предоставляет агенту инструменты. Он не нужен для сборки приложения. Для структурного исследования этого проекта используется `codebase-memory-mcp` вместе со скиллом `codebase-memory`.

Репозиторий содержит `.codex/config.toml`, который ограничивает размер проектных инструкций, каталога скиллов и сохранённого вывода инструментов, использует краткие ответы и отключает только для U-CUDA несвязанные плагины документов, Unity, Blender и управления компьютером. Глобальная конфигурация пользователя при этом не меняется. Проектный файл применяется только к доверенному проекту, открытому из корня репозитория; после его изменения начните новую сессию Codex.

Установите Codex и проверьте доступность CLI:

```powershell
codex --version
codex mcp list
```

Если `codex` не найден, настройте CLI/PATH для своей установки Codex. Конфигурация пользовательских MCP хранится в `~/.codex/config.toml`. Синтаксис команд описан в [официальной документации MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

### Codebase Memory

Установите сервер из дистрибутива [DeusData/codebase-memory-mcp](https://github.com/DeusData/codebase-memory-mcp), следуя инструкции выбранного релиза. Сервер и его установщик не включены в этот репозиторий. Не считайте копирование `SKILL.md` установкой сервера.

На машине, для которой готовилась инструкция, Windows-сервер установлен в `%LOCALAPPDATA%\Programs\codebase-memory-mcp\codebase-memory-mcp.exe`. Для такой установки регистрация выглядит так:

```powershell
$cbmExe = Join-Path $env:LOCALAPPDATA 'Programs\codebase-memory-mcp\codebase-memory-mcp.exe'
if (-not (Test-Path -LiteralPath $cbmExe)) { throw 'Install codebase-memory-mcp first or correct its path.' }
codex mcp add codebase-memory-mcp -- $cbmExe
codex mcp list
```

Если сервер уже зарегистрирован, используйте имеющуюся конфигурацию и сохраните её переменные окружения. При другом расположении замените `$cbmExe`. В Linux укажите путь к установленному исполняемому файлу. Перезапустите сессию Codex после настройки.

Проверка работы через агента:

1. Вызвать `list_projects` / `index_status` именно сервера Codebase Memory.
2. Если индекса нет, вызвать `index_repository` для абсолютного пути корня проекта, а не `.git`, согласно схеме инструмента установленной версии.
3. Проверить схему через `get_graph_schema`, найти символ через `search_graph`, получить исходник через `get_code_snippet`.
4. Проверить покрытие нужных файлов через `check_index_coverage`. Пропущенные или устаревшие участки проверить чтением файлов и `rg`.

Запись в `codex mcp list` подтверждает конфигурацию, но не успешную индексацию. Если инструменты недоступны, явно укажите это и проверяйте исходники напрямую; отсутствие результата в неполном графе не доказывает отсутствие кода.

Дополнительно можно подключить MCP официальной документации OpenAI:

```powershell
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp
```

Другие MCP подключайте по потребности задачи. Blender, Unity и браузерные инструменты не являются зависимостями U-CUDA.

## 6. Установка и использование скиллов

Скилл — каталог с `SKILL.md`, описывающий рабочий процесс. Для этого проекта нужен `codebase-memory` при структурном исследовании; `openai-docs` полезен при настройке самого Codex. Дополнительные скиллы выбираются по задаче.

По [официальной документации скиллов](https://learn.chatgpt.com/docs/build-skills), общие для репозитория скиллы размещаются в `.agents/skills/<name>/SKILL.md`, личные — в `~/.agents/skills/<name>/SKILL.md`. На исходной машине `codebase-memory` уже доступен из `~/.codex/skills/codebase-memory/SKILL.md`; это существующая локальная установка, не переносимый путь проекта.

Для новой машины:

1. Получите каталог нужного скилла из его исходного пакета или репозитория. Для `codebase-memory` используйте пакет, соответствующий установленной версии сервера.
2. Поместите полный каталог с его ресурсами в выбранное расположение скиллов. Не создавайте вторую копию, если скилл уже виден.
3. Откройте новую сессию Codex и проверьте доступность скилла. В CLI его можно явно вызвать через `$codebase-memory`.
4. Проверьте MCP-инструменты отдельно: наличие скилла не подтверждает подключение сервера.

Для установки скилла из известного репозитория можно попросить встроенный `$skill-installer` установить его по точному URL/пути. Не подставляйте случайный одноимённый пакет.

Пример запроса агенту:

```text
Используй $codebase-memory для исследования U-CUDA.
Прочитай корневой и ближайший AGENTS.md, проверь индекс и покрытие нужных файлов.
Перед переносом кода изучи ARCHITECTURE.md.
После изменения выполни проверки, обязательные для затронутого модуля.
```

## 7. Проверки перед сдачей изменений

Для изменений кода соберите затронутые цели и выполните базовые тесты:

```powershell
cmake --build --preset windows-debug
ctest --preset windows-debug -R '^(adaptive_cpu|architecture)$'
git diff --check
```

- При изменении общих вычислительных сигнатур включите и соберите `U-CUDA-legacy`.
- При изменении CUDA/NVRTC выполните `adaptive_gpu` и `gpu_smoke`; для проверки runtime-заголовков используйте чистый каталог сборки/runtime. Пропуск GPU-теста не является успешной проверкой вычислений.
- При изменении границ зависимостей выполните конфигурацию с `U_CUDA_BUILD_GUI=OFF`.
- В Linux выполните применимые платформенные проверки, включая `platform`.
- Выполните дополнительные проверки из ближайшего `AGENTS.md`. Назначение тестов описано в [tests/README.md](tests/README.md).

```powershell
ctest --preset windows-debug -R '^(adaptive_gpu|gpu_smoke)$'
```

В отчёте указывайте выполненные команды, результат и фактические ограничения окружения. Для изменений только документации проверьте команды по конфигурации, локальные ссылки и `git diff --check`; повторная сборка приложения для такой правки не требуется.
