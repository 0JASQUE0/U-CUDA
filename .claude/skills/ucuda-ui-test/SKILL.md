# Тест интерфейса U-CUDA (Dear ImGui Test Engine)

Отдельная сборка приложения с Test Engine (`-DU_CUDA_UI_TESTS=ON`, CMake, каталог
`%TEMP%\ucb-ui`). Это то же приложение, с теми же `libs/ui` и `app_main.cpp`, плюс режим `--ui-*`.
Движок подаёт ввод прямо в ImGui, поэтому реальная мышь, фокус окна и перекрывающие окна ему не мешают.
Справка по командам и ключам — `apps\desktop\ui_test\README.md`. Читать её, когда нужна
команда, которой нет в примере ниже. Все пути здесь — от корня репозитория (скрипты и сценарии
лежат в `apps\desktop\ui_test\scripts` и `scenarios`, сам скилл — в `.claude\skills\ucuda-ui-test`).

Release-сборку из `U-CUDA.sln` это не затрагивает. В `.sln` нет ни движка, ни `ui_test/*.cpp`.

## Порядок работы

1. **Собрать.** Каждый раз после правок кода:
   ```powershell
   & apps\desktop\ui_test\scripts\build.ps1
   ```
   Пересобирается только изменённое (первый раз — несколько минут). `-Reconfigure` нужен, если менялись
   CMakeLists. Ошибки компиляции печатаются, полный лог — `%TEMP%\ucb-ui-build.log`. Сборка `.sln` для
   этого не нужна. Обычные проверки из AGENTS.md (сборка `U-CUDA.sln`, тесты) это не заменяет.

2. **Написать сценарий** `*.uit` в scratchpad, не в репозиторий. Образец —
   `apps\desktop\ui_test\scenarios\smoke.uit`. Сценарий начинается с `ref //MainHost`. Пути к виджетам — ID-пути ImGui:
   `"Phase analysis"`, `"**/Run"`, `"//<окно>/<метка>"`. Метку писать с её `##`-хвостом, путь с
   пробелами — в кавычках.
   - **Сначала — поиск по метке** `"ОКНО>>Метка"` (`*` вместо окна = все окна; `*` в конце метки —
     префикс). Он работает в любой команде, видит поля под PushID, вкладки, комбо и дочерние окна,
     сам прокручивает до скрытых элементов, а по имени докнутого окна выбирает его вкладку дока:
     `click "*>>Bifurcation 2D"`, `input "//Parametric Controls>>Resolution" 101`,
     `select "//Parametric Controls>>Scheme" RK4`, `uncheck "//Controls>>Continuation (live)"`,
     `click "*>>Recompute*"`, `input "//Controls>>##ap_a" 35`.
     Окно тоже можно найти по имени: `"*>>Tree Controls*>>Basins"` (узел дерева, а не верхняя
     вкладка Basins). `@N` — N-е совпадение одинаковых меток: `"//Controls>>##ptype@2"` (вторая
     проекция). Вкладки (`System`/`Parameters` редактора, `Bifurcation`/`LLE`/`LS` параметрики)
     ищутся по имени: `click "//ODE###Editor>>Parameters"`.
   - **Образец полного сценария — `apps\desktop\ui_test\scenarios\Demo_1.uit`**: новая система из статьи (Лю–Чен 2002),
     анализ на всех вкладках, точки на 2D-бифуркационке в Tree со срезами и бассейнами. Запуск для
     показа: `-Fresh -Speed normal -Extra '--ui-size','1920x1080' -TimeoutSec 1800`. Метка — собственная метка виджета
     (справа от поля). Подпись слева отдельным текстом («Step h:» у `##sh`) меткой не считается,
     тогда пиши `##`-имя.
   - Если метки не знаешь — разведка: `find * <префикс>` (все совпадения во всех окнах), `windows`,
     `dump "//<окно>" 2` (ID, метки, флаги `[x]`, `open`, `input`, `disabled`). Кликать можно и по ID.
   - **Графики**: `plots` выводит области графиков (`##plot_N`, `##hm_plot_N`, `##plot3d_N`).
     `plot_hover/plot_click/plot_dclick R X Y [left|right|middle] [Ctrl|Shift…]`, `plot_drag R X0 Y0 X1 Y1 …`,
     `plot_wheel R X Y DY` принимают числа на осях графика (логарифмические и перевёрнутые оси учтены),
     например `plot_click "*>>##hm_plot_*" 40 7.5`. ПКМ — меню графика (Export data, оси), двойной
     щелчок — подгонка, колесо — зум. 3D-графики и прочие свои виджеты — `click_at/drag_at/wheel_at`
     с долями прямоугольника (0..1).
   - **Раскладка окон — без перекрытий.** Добавил окна (проекции на Phase, окна Parametric, виды
     Tree и т.п.) — расставь их кнопкой Layout: `click "//MainHost>>Layout"`, затем
     `click "//$FOCUSED>>Grid"` (2–3 окна — `Columns`/`Rows`, много однотипных — `Tabs`). Новые окна
     по умолчанию ложатся каскадом друг на друга, а пользователь этого не хочет. Проверка:
     `expect_no_overlap`, и скриншот после раскладки.
   - **Файлы**: перед кнопкой, которая открывает диалог, поставь `file_dialog out.csv` (или
     `cancel`), потом проверь `expect_file out.csv`. Без этого диалог отменяется и пишется в лог —
     нативное окно в тестовом режиме не открывается никогда.
   - Прочее: `set_text R "строка1\nстрока2"` (многострочные редакторы, без Enter),
     `click R Ctrl` (модификаторы), `key_down/key_up`, `dock`, `window_close`,
     `clipboard`, `expect_label`, `expect_enabled/disabled`. Полный список — README.
   - После действия, которое перестраивает интерфейс, ставь `yield 3`. Перед проверкой результата
     расчёта — `wait_idle`.
   - Проверки: `expect_mode`, `expect_exists/missing`, `expect_value`, `expect_checked`,
     `expect_open`; чтение значения — `read`. Сценарий останавливается на первой ошибке.

3. **Запустить:**
   ```powershell
   & apps\desktop\ui_test\scripts\run.ps1 -Script <путь>\check.uit -Fresh
   ```
   - **Библиотека изолирована.** В тестовом режиме `U_CUDA_LIBRARY` указывает на
     `%TEMP%\ucb-ui\bin\Release\ui_library` — копию `U-CUDA/library`, которая из оригинала только
     читается. Сессии сохраняются при каждой правке, поэтому без изоляции тесты писали бы в
     настоящую библиотеку (так и было до 2026-11-18). В начале лога должна стоять строка
     `[ui] library (isolated copy): ...`.
   - `-Fresh` — чистые `_app_config.json` и `imgui.ini` и свежая копия библиотеки. Без него
     берётся то, что осталось от прошлых прогонов этой сборки. Пользовательский `x64\Release` не
     трогается никогда.
   - `-Speed normal` — смотреть глазами. По умолчанию `fast`.
   - `-Out <dir>` — куда сложить `log.txt`, `results.xml` и скриншоты (по умолчанию
     `%TEMP%\ucb-ui-out\<имя сценария>`).
   - Скомпилированные тесты: `-Test all` или фильтр по имени (`-Test mode_tabs`).
   Скрипт печатает эхо команд (`[ui] N: ...`), их вывод, строки ошибок (`KO`, `Error`) и итог
   `[ui-summary]`. Код выхода 0 значит, что всё прошло. Полный лог движка лежит в `<out>\log.txt`.

4. **Скриншоты** (`screenshot file.png [окно]`) смотреть через Read. Нужны только когда важен вид
   (графики, раскладка, цвета). Состояние надёжнее проверять командами `expect_*` и `read`.

5. **Обход всех вкладок** — `run.ps1 -Script <загрузка системы>.uit -Test all_tabs -Fresh -TimeoutSec 1750`
   (`ui_tests_sweep.cpp`, около 10 минут). Тест включает скрытые вкладки и на каждой проходит
   все видимые панели вкладок: виджетные, вложенные и вкладки дока. Вкладки-кнопки «+» он
   пропускает. В Library открывает редакторы ODE, DAE и MAP (первая система каждого типа),
   проходит их вкладки и закрывает через Cancel. В каждом окне прокручивает все страницы. Для
   каждого поля ввода:
   - наводит курсор и ловит конфликт ID;
   - открывает правым кликом меню (сводка по вкладке — `[sweep] ... menu xN:`);
   - **правит поле**: читает значение, вводит равнозначное число (`0.01` → `0.010`), читает,
     возвращает исходное и проверяет точное совпадение. `NOT RESTORED` — ошибка теста.
     `EDIT typed … shows …` — поле переписало текст: у слайдеров с форматом `%.2f` и у полей,
     которые форматируют значение сами, это нормально. Многострочные поля пропускаются;
   - **выполняет пункты меню** «Reset to default (v)» и «Restore from library (v)», сверяет поле
     с v и возвращает исходное значение. `ACTION …` — ошибка теста. Поля без меню ПКМ перечислены
     в сводке `no menu in <вкладка>`;
   - **ширина** (у всех полей и комбо с ручкой): перетаскивание на +30, двойной щелчок
     (умолчание), ПКМ (подгонка, меню при этом открываться не должно), снова двойной щелчок.
     Сохранённые ширины после каждой проверки возвращаются как были. Ручки, обрезанные окном или
     ячейкой таблицы, пропускаются (`handle out of view`).
   Перед проверкой закрытые секции и узлы раскрываются.
   Скриншот каждого состояния: `<out>\tabs\N_<вкладка>_<подвкладка>.png`. Одно поле проверяется
   один раз за обход. Переменные окружения: `UCUDA_SWEEP_ONLY=<часть названия вкладки>`,
   `UCUDA_SWEEP_VERBOSE=1` (счёт по окнам и страницам), `UCUDA_SWEEP_NOEDIT=1` (без правок и
   действий меню), `UCUDA_SWEEP_NOWIDTH=1` (без проверок ширины), `UCUDA_SWEEP_NOOPEN=1` (не
   раскрывать секции). Полный прогон — около 3 минут. Не покрывает: содержимое комбо, «Apply to…»
   по каждому полю, поля, которые появляются только после Run, кнопки и диалоги.

6. **Регрессии** — если проверка должна жить дальше, оформи её C++-тестом в
   `apps/desktop/ui_test/ui_tests.cpp`. Там есть `IM_CHECK*` и прямой доступ к `AppModel` через
   `ui_test::app_model()`. Прогон: `run.ps1 -Test all`.

## Ограничения и грабли

- Попапы закрывает `key Escape`, по уровню за нажатие (обработчик в `gui.cpp`; модальные окна —
  своими Cancel) — или `popup_close`. Если курсор остался на пункте, открывающем подменю, ImGui
  откроет его снова по наведению: сначала `hover` внутрь подменю. Пока попап открыт, наведение
  на поля под ним не работает («Unable to Hover»).
- Система по умолчанию не выбрана. Загрузить: `select 0x7BF9F62D Chen` (комбо систем в `MainHost`).
  Сценарий с `-Test` выполняется ПЕРЕД скомпилированными тестами — так он готовит состояние для них.
- У пресета Chen на Phase включён Continuation (live): расчёт бесконечный, и `wait_idle` не дождётся.
  Сначала `uncheck "//Controls>>Continuation (live)"`.
- Метки со счётчиком или состоянием («Reset to default (0)», «Bif N=100###…») — префиксом:
  `click "W>>Reset to default*"`.
- Параметрика сохраняет сессию bif/LLE/LS только после расчёта (poll) или смены палитры. Правка полей без
  Run в библиотеку не попадает.
- ID-пути (`"//##Combo_00/Euler"`) и ID из `dump` по-прежнему работают. ID поля зависит от пути, а не от
  положения, поэтому между прогонами он стабилен.
- Окно приложения появляется на экране (1600x900, `--ui-size`), и это нормально: рисовать нужно в
  настоящий framebuffer. Курсор пользователя не перехватывается.
- `read` и `expect_value` читают значение через выделение и копирование в тестовый буфер обмена.
  Для полей это работает, для текста-надписи — нет. Текст проверяется через `dump` (метка в `"..."`).
- Метки в `dump` обрезаны до 32 символов. Для длинных меток — поиск по префиксу (`W>>начало*`).
- Окна-потомки (`BeginChild`) имеют искажённые имена. Поиск по метке в окне их уже включает.
- Комбо получают метку для движка только в UI-сборке: `third_party/CMakeLists.txt` компилирует копию
  `imgui_widgets.cpp` с хуком в `BeginCombo`. При обновлении ImGui якорь может пропасть — CMake
  тогда остановится с ошибкой.
- ImGui в CMake закреплена на `v1.92.8-docking`, движок — на тег `v1.92.8`
  (`third_party/CMakeLists.txt`). Обновлять оба вместе.
- Лицензия Test Engine: бесплатно для частных лиц и учебных целей. Движок не распространять внутри
  Release-сборки.
