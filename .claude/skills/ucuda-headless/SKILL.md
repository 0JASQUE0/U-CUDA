# U-CUDA без GUI

`ucuda_run.exe` — раннер поверх объектников Release-сборки (`parametric_engine`, `codegen`, ...).
Система и задача описываются текстовым job-файлом; результат — CSV в «длинном» формате, который
сразу читается pandas/numpy. Код и ядра — те же, что у вкладок Parametric / Basins / Metrics / DFT.

Пути ниже — относительно каталога этого скилла (`.claude\skills\ucuda-headless` в корне репозитория).

## Порядок работы

1. **Раннер собран и актуален.** Всегда сначала:
   ```powershell
   & .claude\skills\ucuda-headless\build.ps1
   ```
   Скрипт обновляет `bin\kernels\` из `x64\Release\kernels` и перелинковывает exe, только если
   объектники новее. Предупреждение «*.cpp новее *.obj» значит, что Release не пересобран —
   решить с пользователем, пересобирать ли (`U-CUDA.sln`, Release|x64, MSBuild полным путём).
   Если правился код движка или шаблоны — пересобрать Release, иначе раннер считает старым кодом.

2. **Job-файл.** Писать в каталог результатов пользователя (или в scratchpad для пробы), не в
   репозиторий. Образцы: `examples\lorenz_bif1d.job`, `examples\rossler_lle2d.job`. Все ключи,
   умолчания и форматы CSV — в `reference.md`; читать его, когда нужен ключ, которого нет в примерах.
   Минимум: `task, vars, params, rhs (по строке на переменную), values, ic, h, transient, tmax,
   sweep, range, n, out`.

   Система из библиотеки (`U-CUDA\library\<Имя>\system.json`): `vars_text` → `vars`,
   `params_text` → `params` (в ЭТОМ порядке), значения из `param_values` переписать в том же порядке,
   `init_conditions` → `ic`, `step_h` → `h`, `symmetry_s` → `s`. Правые части переписать из
   `latex_text` / `plain_text` в обычный синтаксис (`sigma*(y - x)`, `x^2`, `abs`, `sin`, `min`).
   Если система использует вспомогательные функции (`use_aux_funcs`) — подставить их тела вручную.

3. **Запуск** — из каталога, где должны лечь файлы (`out` — префикс, относительный или абсолютный):
   ```powershell
   & .claude\skills\ucuda-headless\bin\ucuda_run.exe job.txt [key=value ...]
   ```
   `key=value` в командной строке заменяют значения файла — так делаются серии:
   ```powershell
   foreach ($sc in 'RK4','CD','DOPRI78') { & $exe job.txt scheme=$sc out="ls_$sc" }
   ```
   Первая сборка модуля NVRTC — секунды (с `rdc = 1`, умолчание раннера); счёт большой сетки может
   идти минутами — такие прогоны запускать в фоне (`run_in_background`). Прогресс идёт в stderr,
   итог — одна строка `OK <task> ..., <t> s -> <file>` или `FAILED/ERROR: ...` с кодом выхода 1.

4. **Результат.** `<out>_<task>.csv` + `<out>_run.txt` (фактический job со всеми подстановками,
   время, ошибка) — его и сохранять рядом с данными для воспроизводимости. Быстрая картинка:
   ```powershell
   python .claude\skills\ucuda-headless\plot.py <out>_<task>.csv [столбец]
   ```
   Для публикационных фигур писать свой matplotlib-скрипт файлом (не через `python -c`).
   Показывать пользователю PNG и коротко — что видно (режимы, диапазоны показателей), а не CSV.

## Что важно не перепутать

- **a[] и значения.** `values` — только параметры, в порядке `params`. Слот a[0] = `s` (коэффициент
  симметрии CD/SEMP/SIMP/Complex CD, умолчание 0.5); хвост Ньютона/CD FP раннер дописывает сам.
  `sweep = s` свипует a[0].
- **Схема** — имя как в GUI: `RK4`, `CD`, `CD fast`, `DOPRI78`, `DOP853`, `RK45`, `Implicit Euler`,
  `Implicit Midpoint`, `SEMP`, `GBS 2-4`, `Complex CD4`, ... (полный список — `reference.md`).
  Неизвестное имя — ошибка (раннер не даёт молча скатиться в Euler, как `scheme_from_name`).
  RK45/DOP853/DOPRI78 здесь — **постоянный** шаг.
- **Свой метод (тело КРС)** — `body_file = путь` к телу `calculateDiscreteModel` (например, из
  `custom_schemes[].body` в system.json). `dump_body = 1` пишет сгенерированное тело в `<out>_body.cu`.
- **Дискретное отображение** — `map = 1` (схема игнорируется), для БД обычно `all_samples = 1`.
- **Явное время t** в правых частях работает само (кодоген видит `t`).
- **Совпадение с GUI бит-в-бит** требует тех же глобальных настроек, что в `x64\Release\_app_config.json`:
  `rdc` (раздельная сборка меняет последние биты на части схем), `fmad`, настройки пиков. Раннер по
  умолчанию: `rdc = 1, fmad = 1`, пики — константы `configCUDA.h`.
- **Конечное время LLE/LS** даёт точечный шум ~ln(1/eps)/tmax — это не ошибка; помогает
  `vector_transient`. LLE/LS не видят равновесие: смотреть столбец `flag` и/или `bif1d` на режим.
- **numb** — как в собранном Release (`configCUDA.h`, сейчас double). Для float — отдельная
  сборка движка, этим раннером не делается.

## Чего раннер не умеет (нужен свой пробник)

Адаптивный шаг, DAE-методы, обёртки `Extr(...)`/`Comp(...)`, FastSync, Network, вкладка Order,
фазовый портрет одной траектории. Для них — свой `main()` по образцу `runner\ucuda_run.cpp`
(запросы — `U-CUDA\parametric_engine.h`, кодоген — `codegen.hpp`), собранный тем же `build.ps1`
с добавлением нужных объектников (`analysis_session`, `nvrtc_engine`, ... — каждый тянет свои
зависимости и заглушки). Не править под это исходники проекта и `.vcxproj`.

## Если сломалось

- `LNK2019` при сборке раннера — в проекте появилась новая зависимость: добавить объектник в
  список `$objs` в `build.ps1` или заглушку в `runner\stubs.cpp`.
- NVRTC не находит заголовок / шаблон — `bin\kernels\` устарел: перезапустить `build.ps1`
  (он копирует свежий `x64\Release\kernels`).
- Компиляция модуля идёт минутами — включён монолит (`rdc = 0`) на большом теле: так и должно быть,
  см. «How a sweep module is compiled» в CLAUDE.md.
